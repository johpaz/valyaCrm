## What shipped
- `GET /api/v1/crm/oportunidades?vendedorId=…`: the rep's opportunities
  (hard cap 20, sorted by `fechaActualizacion` descending), each with
  `empresa` (nombre, sector, ubicacion), `contacto` (nombre, cargo, telefono,
  email), `producto` (nombre) and `cantidadActividades`; `[]` when none; 400
  for a missing or malformed id; generic 500; JSON content type.
- `crmService.listarOportunidadesDeVendedor` and `darFormaOportunidad`; the AI
  agent's `obtenerOportunidadesPorVendedor` unchanged.
- First route-level `bun test` file (`crmRoutes.test.ts`).

## Known issues and tech debt
- Hard cap of 20, no pagination (PM decision for the test phase); extra
  opportunities are silently left out.
- `fechaActualizacion` is only set on creation (updates use
  `findByIdAndUpdate`, skipping the save hook), so the order is effectively
  newest-created first. Fix planned in 2.3.
- Field-name differences 2.6 must bridge: `_id` vs `id`, `empresa.nombre` vs
  `empresaNombre`, backend `estado` values vs the frontend's, `notas` as a
  list, `ubicacion` on the company.
- Test data in `crm_vendedor_b2b`: "Prueba UAT 2.1 …" company, contact,
  product and two opportunities (for 5.1).
