Plan: One way to mark a deal as won
ID: 2.10
Date: 2026-10-10
Round: 1 (revised 2026-10-10 after PM review: two close dates, self-repair)
Goal: Give the app and the WhatsApp agent one shared "mark as won" action that
records exactly one sale (amount, actual close date, optional comment) and
moves the deal to "Cerrado Ganado", keeping the expected close date, and remove
the sale when a won deal is moved back.

## Out of scope
- The app's dialog (2.6, whose story must be revised first); lost deals;
  currency; editing a recorded sale; making agent writes succeed (6.1) or
  matching misspelled stages from WhatsApp (6.2).

## Request and responses
```
POST /api/v1/crm/oportunidades/:id/ganada
{ "valorCierre": 125000000, "fechaCierreReal": "2026-10-08", "comentario": "Firmado" }
  (fechaCierreReal optional, defaults to today; comentario optional)
200 { …the opportunity in the 2.2 detail shape, estado "Cerrado Ganado",
      valorCierre and fechaCierreReal set, fechaCierre (expected) unchanged… }
400 { "error": "El monto final debe ser un número mayor que cero." }
400 { "error": "El comentario no puede superar los 500 caracteres." }
400 { "error": "La fecha de cierre no puede ser futura ni anterior a la creación de la oportunidad." }
400 { "error": "El id de la oportunidad no tiene un formato válido." }
404 { "error": "Oportunidad no encontrada." }
409 { "error": "Esta oportunidad ya está marcada como ganada." }
```
And on the 2.3 stage update, `PATCH …/estado` with "Cerrado Ganado" gets:
`400 { "error": "Para marcar la oportunidad como ganada, registra la venta con su monto final." }`

## Files affected
- `src/models/oportunidadModel.ts`: new optional `fechaCierreReal` (actual
  close date); `fechaCierre` stays the expected date.
- `src/types/index.ts`: `fechaCierreReal` and `valorCierre` on the Oportunidad
  type; `comentario` on VentaGanada.
- `src/models/ventaGanadaModel.ts`: optional `comentario` (trimmed, max 500);
  `oportunidadId` unique, so a second sale for a deal can never be saved, even
  with two requests at once (no sales exist yet, so the rule applies cleanly).
- `src/services/crmService.ts`:
  - new `marcarOportunidadComoGanada(id, { valor, fechaCierreReal, comentario })`:
    checks the deal and the date, records the sale (with the deal's
    `vendedorId`; the sale's `fecha`, `mes` and `año` from the actual close
    date), then sets `estado`, `valorCierre` and `fechaCierreReal`; if that
    update fails, the sale is removed again. If a sale already exists but the
    deal isn't won (an interrupted attempt), it updates that sale and finishes
    the deal instead of refusing.
  - `crearVentaGanada` (the agent's sale tool) now uses it.
  - `actualizarOportunidad` (the 2.3 route and the agent's update tool):
    refuses `estado: "Cerrado Ganado"`; when a won deal moves to another stage,
    removes its sale and clears `valorCierre` and `fechaCierreReal`, keeping
    `fechaCierre`.
- `src/services/toolsManager.ts`: the two tool descriptions say how to mark a
  deal won (`oportunidadId`, `valor`, optional `comentario`) and that the
  update tool cannot.
- `darFormaOportunidad` (2.1/2.2 shape): adds `valorCierre` and
  `fechaCierreReal`, so the board can show both dates.
- `src/routes/crmRoutes.ts`: `POST /oportunidades/:id/ganada`; the 2.3 route
  turns the new refusal into its 400.
- Tests: `src/services/crmService.test.ts`, `src/routes/crmRoutes.test.ts`,
  `src/models/ventaGanadaModel.test.ts` (new).
- `CLAUDE.md`: the new endpoint and the changed 2.3 entry.
- `docs/plans/2.10-plan.md`; `docs/releases/2026-10-09-2.3-merge.md`.

## Risks
- Changes two agent tools' behaviour (the sale tool, and the update tool
  refusing "won" and removing a sale on reopen): flagged for johpaz in the PR.
- No database transactions are used (the setup may not support them). An
  error between saving the sale and updating the deal removes the sale again;
  a crash in that instant is repaired by the next attempt (criterion 7).
- Live testing changes "Prueba UAT 2.1 …" test data (cleaned in 5.1).

## Decisions
- `POST /oportunidades/:id/ganada` with `valorCierre` and `comentario`: an
  action, separate from the stage update.
- The sale's rep comes from the deal, never from the caller.
- The one-sale rule lives in the database (unique `oportunidadId`) as well as
  in the code, so simultaneous requests cannot both succeed.
- Won/reopen rules live in `actualizarOportunidad`, so the app's stage update
  and the agent's update tool behave the same.
- Two dates (PM): `fechaCierre` is always the expected date; the actual date is
  `fechaCierreReal`. The sale's month and year follow the actual date, so the
  dashboard files a late-recorded win in the right month.
- The 2.10 story is committed through its own `valya_front` docs PR (#17), the
  practice for backend features from now on (PM, 2026-10-10).
