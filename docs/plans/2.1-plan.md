Plan: List opportunities by rep
ID: 2.1
Date: 2026-10-09
Round: 1
Goal: Add `GET /api/v1/crm/oportunidades?vendedorId=…`, returning up to 20 of
the rep's opportunities with their company, contact and product included, so
the CRM board (2.6) can show real deals.

## Out of scope
- Wiring the CRM board (2.6), get-by-id (2.2), stage update (2.3).
- Filtering, sorting options or pagination; the `/buscar` endpoints (2.9).
- Authentication (decision #1).
- Changing what the AI agent's `listar_oportunidades` tool returns.

## Response shape
```
200 [
  {
    "_id": "…", "nombre": "…", "estado": "Negociación",
    "valorEstimado": 0, "comision": 0, "fechaCierre": "…",
    "fechaCreacion": "…", "fechaActualizacion": "…",
    "notas": ["…"], "proximosPasos": "…",
    "cantidadActividades": 3,
    "empresa":  { "_id": "…", "nombre": "…", "sector": "…", "ubicacion": "…" } | null,
    "contacto": { "_id": "…", "nombre": "…", "cargo": "…", "telefono": "…", "email": "…" } | null,
    "producto": { "_id": "…", "nombre": "…" } | null
  }
]
400 { "error": "…" }   missing or malformed vendedorId
500 { "error": "No se pudieron obtener las oportunidades." }
```
Names follow 1.4's frontend fields (`empresa`/`contacto`, `cantidadActividades`).

## Files affected

  `obtenerOportunidadesPorVendedor` is untouched.
- `src/routes/crmRoutes.ts`: `GET /oportunidades` with `vendedorId` validation.
- `src/services/crmService.test.ts` and `src/routes/crmRoutes.test.ts` (new):
  bun tests.
- `CLAUDE.md`: the new endpoint under "Current API endpoints".
- `docs/plans/2.1-plan.md` (this file).

## Steps

## Tests
- Criterion 1 [BOTH]: route test returns 200 and the service's list for a
  valid id; service test checks the query filters by that rep, sorts by most
  recently updated, limits to 20, and populates company, contact and product.
  Live call.
- Criterion 2 [BOTH]: route test for an empty list returns 200 `[]`. Live
  call with a test rep that has no opportunities.
- Criterion 3 [BOTH]: `darFormaOportunidad` test: populated relations appear
  as `empresa`, `contacto`, `producto`, missing ones as `null`, and
  `cantidadActividades` counts the activities. Live call.
- Criterion 4 [BOTH]: route tests for a missing and a malformed `vendedorId`
  return 400 without calling the database; a database failure returns 500 with
  a generic message.
- Criterion 5 [UAT]: the path and Spanish names, checked in the PR.

## Risks
- FYI for testers (PM, 2026-10-09: keep 20 for the test phase): if a rep has
  more than 20 opportunities, only the 20 most recently updated are returned;
  the rest do not appear on the CRM board and nothing says so. Closed deals
  count too, so a rep with history can pass 20. Options if testers hit it:
  raise the cap (for example to 100), or add pagination.
- The live check needs a rep that has opportunities. If none exists in the
  shared database, I will add a few test opportunities to the test rep
  ("Prueba UAT 1.3 lento"), named "Prueba UAT 2.1 …", for 5.1 to clean up.
- Opportunities with a deleted company, contact or product show `null` for it
  rather than failing.

## Decisions
- A dedicated service method instead of extending the agent's: the story warns
  that changing `obtenerOportunidadesPorVendedor` would change the AI tool's
  output.
- The 20 shown are sorted by `fechaActualizacion`, newest first. Review
  finding: that field is only set on creation (updates use
  `findByIdAndUpdate`, which skips the save hook), so in practice the newest
  created come first; fixing the update paths belongs to 2.3.
- Only the fields the card needs are taken from related records; this also
  keeps the company's large `embedding` array out of the response.
- `vendedorId` in the query string (`?vendedorId=`), like `/reportDash/report`.
- A malformed id is a 400; a well-formed id with no opportunities is an empty
  list, as the story asks (no separate "unknown rep" check).
- The 500 message is generic, so internal errors are not exposed.
- The plan lives in `valyaCrm` because the work happens there; the 1.5 merge
  record goes into `valya_front` with the other merge records, through its own
  small docs PR.
